🛡️ Ubuntu Security Handbuch für C/C++ Pakete & Systembibliotheken

Dieses Dokument beschreibt die offiziellen Informationsquellen, Sicherheitsportale sowie Terminal-Befehle zur Überprüfung und Absicherung einzelner C/C++-Pakete und Systembibliotheken auf Ubuntu Linux.

1. Offizielle Ubuntu Security Webseiten & CVE-Datenbanken

Canonical stellt dedizierte Portale bereit, um den Sicherheitszustand aller in Ubuntu verwendeten C-Bibliotheken (glibc, openssl, zlib, curl, libssl etc.) einzusehen:

  • Ubuntu Security Notices (USN):
    🔗 https://ubuntu.com/security/notices
    Hier veröffentlicht Canonical alle offiziellen Sicherheitswarnungen und veröffentlichten Fixes für C-Bibliotheken und Pakete unter Ubuntu.

  • Ubuntu CVE Tracker:
    🔗 https://ubuntu.com/security/cve
    Ermöglicht die gezielte Suche nach Sicherheitslücken (CVEs) für einzelne C-Pakete (z. B. glibc, openssl, zlib, curl, libssl).

  • Ubuntu Package Directory:
    🔗 https://packages.ubuntu.com
    Übersicht aller Pakete und deren Herkunft aus den Repositories (main, universe, security).

2. Befehle auf dem Ubuntu-Terminal zur Prüfung einzelner C-Pakete

Zur Diagnose und Sicherheitsüberprüfung lokaler Ubuntu-Systeme dienen folgende Befehle:

  • pro status (oder ubuntu-security-status):
    Prüft den allgemeinen Sicherheits- und ESM-Status (Expanded Security Maintenance) Ihres Ubuntu-Systems.

  • apt-cache policy <paketname>:
    Zeigt die exakt installierte Paketversion sowie die Herkunft (z. B. noble-security, jammy-security) für ein spezifisches C-Paket an:

    apt-cache policy libc6 libssl3 curl

  • debsecan:
    Analysiert das laufende Ubuntu-System auf alle aktuell bekannten CVE-Sicherheitslücken in den installierten Paketen:

    sudo apt install debsecan
debsecan

3. Sicherheitsarchitektur der C-ABI in MeinCMS (meincms_parser)

Die C-ABI Schnittstelle in meincms_parser profitiert von den Sicherheitsgarantien der Rust-Laufzeitumgebung:

  1. Speichersicherheit (Memory Safety):
    Rust führt vor dem Export an die C-ABI strikte Bounds-Checks und UTF-8-Validierungen durch. Dadurch werden klassische C-Pufferüberläufe (Buffer Overflows) ausgeschlossen.
  2. Explizite Speichergabe:
    Die C-API stellt die Funktion meincms_free_string(*mut c_char) bereit, die C/C++-Entwicklern eine kontrollierte Freigabe des Rust-Heap-Speichers garantiert.
  3. Ubuntu Compiler Hardening Flags:
    Bei der Einbindung von libmeincms_parser.so in eigene C/C++-Programme unter Ubuntu sollten folgende GCC/Clang-Hardening-Flags verwendet werden: 
    gcc -O2 -fstack-protector-strong -D_FORTIFY_SOURCE=2 -fPIE -pie -Wl,-z,relro,-z,now main.c -lmeincms_parser -o main_app
